## 1. لماذا تتغيّر الحاوية بصرياً رغم `min-height: 0` و `minmax(0, 1fr)`؟

### 1.1 الاستنتاج المباشر من القياس الصحيح (بعد إصلاح المسبار)

التحليل السابق (`P4_FINAL_CONTAINER_VISUAL_ANALYSIS.md`) قاس **الارتفاع فقط** وخلص إلى "ثبات تام". القياس الشامل الجديد — بعد إصلاح خطأ المسبار الذي كان يلتقط DOM خالياً — يُظهر الحقيقة الكاملة:

**الارتفاع ثابت فعلاً (433px لكل الحالات)، لكن العرض متغيّر بشدة (843px → 1032px → 1238px).**

| الحالة | `.p4-container` (عرض/ارتفاع) | `.p4-card` (يسار..يمين / ع × ا) | `.p4-svg-zone` (ع × ا) | `.p4-steps-panel` (ع × ا) | `.p4-nav` (يسار..يمين / ع × ا) |
|--------|------------------------------|---------------------------------|------------------------|---------------------------|--------------------------------|
| **ب** (ba, letter=0 step=0) | `135..1231` → 1096 × 645 | `167..1199` → **1032 × 433** | **467 × 367** | **467 × 367** | `167..1199` → 1032 × 60 |
| **ث-مراجعة** (tha-step4, letter=2 step=4, نص 81 حرفاً) | `32..1334` → **1302 × 645** | `64..1302` → **1238 × 433** | **570 × 367** | **570 × 367** | `64..1302` → 1238 × 60 |
| **ن** (nun, letter=3 step=0) | `229..1137` → **907 × 645** | `261..1105` → **843 × 433** | **373 × 367** | **373 × 367** | `261..1105` → 843 × 60 |

نقاط حاسمة:
- **الارتفاع ثابت**: card h=433، svg/steps h=367، nav top=625، cont top=59/bot=704 — لكل الحالات.
- **العرض متغيّر**: البطاقة تتبدّل بين **843 / 1032 / 1238** px — وهذا بالضبط ما يراه المستخدم ("تكبر عند ث والخطوة الخامسة وتنكمش عند ن").
- **الحافة الداخلية للأعمدة مثبّتة عند مركز البطاقة**: svg يساره ثابت عند x=699، وsteps يمينه ثابت عند x=667 (الفجوة gap بينهما 32px حول المركز x=683). أي أن العمودين "يتمددان للخارج من المركز" عند طول النص، فلا يتغيّر عرضهما فقط بل **مواقع محتوى SVG والأزرار** كما وصف المستخدم.

### 1.2 لماذا فشل `min-height:0` و `minmax(0,1fr)` في إيقاف التغيّر؟

لأنهما **يقيّدان المحور الرأسي فقط (الارتفاع)**:
- `min-height: 0` + `flex: 1` على `.p4-card-wrapper` + `grid-template-rows: minmax(0, 1fr)` على `.p4-card` = يمنعان البطاقة من التمدد **عمودياً** تحت ضغط نص الخطوات. هذا نجح فعلاً (h=433 ثابت).
- لكن **لا يوجد أي قيد على المحور الأفقي (العرض)**:
  1. `.p4-container` (سطر 1698) **بدون `width` ولا `max-width`** — وهو flex item داخل `#content-zone` (`display:flex; justify-content:center; align-items:flex-start`)، فعرضه الافتراضي `auto` يعني **يتبع عرض المحتوى الضمني (max-content)**.
  2. `.p4-card` لديه `width:100%` من حاوية عرضها هو نفسه محتوى — لا توجد نقطة تثبيت عرض ثابتة في السلسلة كلها.
  3. شبكة `.p4-card` (`grid-template-columns: 1fr 1fr`) بأعمدة `1fr` — عند عدم وجود عرض محدد للحاوية، يتحدد حجم الأعمدة من **intrinsic max-content** للمحتوى، أي من أطول نص في `.p4-steps-panel` (نص مراجعة ث = 81 حرفاً → أعرض عمود؛ نص ن الأقصر → أضيق عمود).

**الخلاصة**: قيود "الحل D" السابقة أثبتت **المحور العمودي فقط**. المحور الأفقي بلا أي حاوية خارجية تحدده، لذلك البطاقة "تنكمش/تتمدد" أفقياً مع طول النص — وهذا التغيّر البصري الحقيقي الذي لاحظه المستخدم.

## 2. أي عنصر في السلسلة يسمح بتغيّر الحجم؟

السلسلة: `#content-zone` ← `.p4-container` ← `.p4-card-wrapper` ← `.p4-card` ← `.p4-steps-panel` (+ `.p4-svg-zone`)

### 2.1 المشغّل الجذري (Root cause)

| الرتبة | العنصر | المسؤولية | لماذا يسمح بالتغيّر |
|--------|--------|-----------|----------------------|
| **1 (الجذر)** | `.p4-container` | عرض `auto` بلا `width`/`max-width` | كعنصر flex داخل `#content-zone` المحوري/الموسّط، عرضه = max-content — **يتبع المحتوى** |
| **2** | `.p4-card` (الشبكة `1fr 1fr`) | أعمدة `1fr` بلا `minmax(0,1fr)` أفقية | عند عرض حاوية غير محدد، `1fr` يتحول إلى max-content — ينشر عرض أطول نص |
| **3** | `.p4-steps-panel` (المحتوى) | النص الأطول (نص مراجعة ث 81 حرفاً) | مصدر الـ max-content؛ الأعمدة تتبادل العرض بالتساوي بين SVG والخطوات |
| 4 | `.p4-card-wrapper` | `flex:1` + `min-height:0` | **يقيّد العمود فقط**؛ لا يقيّد العرض (غير مسؤول عن المشكلة) |
| 4 | `.p4-svg-zone` | `max-width:280px` على `.stroke-svg` فقط | **SVG نفسه محدد** (280px) لكن مساحة العمود تبقى من steps |

### 2.2 الآلية الدقيقة (بأرقام القياس)

- عمودا الشبكة متساويان دائماً (`1fr 1fr`): لـ ب كل عمود 467px، لث-مراجعة 570px، لن 373px.
- الفجوة المركزية (667..699 = 32px) مثبّتة حول مركز الشاشة x=683؛ أي أن نمو العرض يتم **إلى الخارج من المركز** في الاتجاهين، وليس تمدداً أحادي الجانب.
- لذلك مع ث-مراجعة: `.p4-svg-zone` يتمدد يميناً (يمينه 1072→1269) و`.p4-steps-panel` يتمدد يساراً (يساره 294→97)، و`.p4-nav` يتباعد زرّا السابق/التالي مع عرض البطاقة — **كل ما وصفه المستخدم**: "تتغير مواضع SVG والأزرار".

### 2.3 الخطأ في التحليل السابق

`p4_probe_out3.txt` قاس **cardH فقط** (max-min=0) واعتبره دليل ثبات. لم يُقَس العرض، لأن القياس كان محصوراً في متغيرات الارتفاع. المستخدم كان محقاً: **العرض هو المتغيّر**، والارتفاع وحده لا يكشفه.

## 3. أفضل تصميم معماري لتحقيق "Container defines size. Content adapts."

### 3.1 المبدأ الصحيح

```
الحاوية الخارجية تحدد الحجم (العرض والارتفاع معاً)
  └── المحتوى يتكيف داخل الحاوية (تقصير/التفاف/scroll داخلي)
```

يجب أن توجد **نقطة تثبيت عرض واحدة** في السلسلة، تكون الحاوية هي المالك الوحيد للحجم، فلا يوجد أي مسار يسمح للمحتوى بفرض حجمه على الحاوية.

### 3.2 التغييرات المعمارية الموصى بها (للمراجعة، لم تُطبَّق)

1. **تثبيت عرض `.p4-container`**: إضافة `width: 100%` + `max-width` (مثلاً `1100px` أو `1140px`) مع `margin-inline: auto`، أو `width: min(100%, 1100px)`. هذا يجعل الحاوية تحدد العرض بدل المحتوى.
2. **حصر الأعمدة داخل العرض المحدد**: تغيير `.p4-card` إلى `grid-template-columns: minmax(0, 1fr) minmax(0, 1fr)` — حتى لا تتسع الأعمدة عن مساحتها عند طول النص.
3. **منع النص من فرض max-content**: على `.p4-steps-panel` إضافة `min-width: 0`، وعلى `.p4-step-body`/`.p4-step-desc` السماح بالالتفاف (هي أصلاً `-webkit-line-clamp:2` + overflow) مع ضمان `min-width:0` حتى لا يدفع النص العرض.
4. **الاحتفاظ بقيود الارتفاع الحالية كما هي**: `min-height:0`، `minmax(0,1fr)`، `max-height:100%` + `overflow-y:auto` على لوحة الخطوات — هذه أثبتت نجاحها في تثبيت الارتفاع 433px.

### 3.3 معايير القبول (تحديث)

| المعيار | القياس الحالي (غير المصحح) | المطلوب بعد الحل |
|---------|----------------------------|------------------|
| نفس ارتفاع البطاقة | ✅ 433px ثابت | ✅ يبقى 433px |
| **نفس عرض البطاقة** | ❌ 843/1032/1238 | ✅ متطابق لكل الحروف |
| نفس موقع SVG وsteps | ❌ الأعمدة تتبدل عرضاً | ✅ ثابتة |
| نفس موضع أزرار nav | ❌ تتباعد مع العرض | ✅ ثابتة |
| لا تمدد من نص 81 حرفاً | ❌ يتمدد العرض | ✅ يلتف/يُقص داخل العمود |

## 4. الحل النهائي المقترح: تثبيت الحجم على أكبر حالة (ث)، كل الحروف بنفس الأبعاد

### 4.1 الفكرة

"الحاوية تحدد الحجم" تعني أن **أكبر محتوى (ث + مراجعة نص 81 حرفاً)** يجب أن يُحجَم داخل نفس المساحة التي تُستخدم لكل الحروف، لا أن يُوسّعها. لذلك:

1. **تثبيت عرض الحاوية** على قيمة تتسع لأكبر حالة بشكل مريح عند 1366×768 (مثلاً عرض بطاقة ~1100–1150px) — بحيث تكون حالة ث-مراجعة هي "الحد الأقصى المحسوب له"، وكل الحروف الأخرى تظهر بنفس الأبعاد تماماً.
2. **تثبيت الارتفاع** على أكبر حالة: الـ 433px الحالية تتسع لـ 5 خطوات + النص الأطول بدون scroll (مؤكد بالقياس: `stepsScroll=no` عند 1366×768). يُبقى هذا الارتفاع نفسه لكل الحروف.
3. **كل الحروف بنفس الأبعاد**: بما أن الحاوية هي المالك للعرض والارتفاع، تصبح Rects `.p4-container` / `.p4-card-wrapper` / `.p4-card` / `.p4-svg-zone` / `.p4-steps-panel` / `.p4-nav` **متطابقة البكسل لكل الحروف** — لا تغيّر SVG ولا steps ولا أزرار.

### 4.2 التغيير CSS المحدد (نُفِّذ في `css/style.css`)

```css
/* 1) الحاوية تحدد العرض — لا المحتوى */
.p4-container {
  width: 100%;                    /* كان: بلا width (auto → max-content) */
  max-width: 1100px;              /* نفس لغة التصميم P2/P3 */
  min-width: 0;
  margin-inline: auto;            /* البقاء موسّطاً داخل #content-zone */
}

/* 2) الأعمدة تبقى داخل الحاوية ولا تتمدد بالنص */
.p4-card {
  grid-template-columns: minmax(0, 1fr) minmax(0, 1fr);  /* كان: 1fr 1fr */
}

/* 3) منع النص من فرض عرض الحاوية */
.p4-steps-panel { min-width: 0; }        /* إضافة (سطر 1821) */
.p4-svg-zone    { min-width: 0; }        /* إضافة (سطر 1776) */
.p4-step-body   { min-width: 0; }        /* موجودة سطر 1876، تُؤكَّد */
```

(باقي قيود الارتفاع: `flex:1; min-height:0; overflow:hidden` على الـwrapper، و`grid-template-rows: minmax(0,1fr); height:100%` على البطاقة، و`max-height:100%; overflow-y:auto` على اللوحة — تُبقى كما هي.)

### 4.3 خطوات التحقق بعد التطبيق (مقترح)

1. إعادة تشغيل `p4_shot_probe.html` بالتدفقات الستة (ب/ث-مراجعة/ن عند 1366×768 و1366×462).
2. التحقق أن `card w` و`card h` و`svg` و`steps` و`nav` متطابقة في كل الحالات (max-min = 0 على المحورين).
3. فحص بكسلي للقطات light: عرض البطاقة الأبيض متطابق (±1px).
4. التأكد من `stepsScroll=no` عند 1366×768 (لا تمدد) ومن الالتفاف/القص بدل التمدد عند الطول الأقصى.
