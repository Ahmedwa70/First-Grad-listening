## 1. وصف المشكلة

بعد حل مشكلة قطع النص (P4_LAYOUT_ANALYSIS)، ظهرت مشكلة **ثبات الحاوية** عند الانتقال بين الحروف:

### السلوك الحالي:
- حروف **ب، ت، ن** (4 خطوات): ارتفاع البطاقة = **672px**
- حرف **ث** (5 خطوات): ارتفاع البطاقة = **738px**
- **فرق = 66px** في ارتفاع البطاقة عند الانتقال إلى/من حرف "ث"

### التأثير البصري في الفصل:
| العنصر | 4 خطوات (ب/ت/ن) | 5 خطوات (ث) | الفرق |
|--------|-----------------|-------------|-------|
| ارتفاع البطاقة | 672px | 738px | **+66px** |
| ارتفاع لوحة الخطوات | 255px | 322px | **+67px** |
| موقع شريط التنقل (navY) | 839px | 906px | **+67px** |
| ارتفاع منطقة SVG | 319px | 319px | **ثابت** ✓ |

### ما يراه المعلم والطلاب:
1. **قفزة بصرية**: عند الضغط على "التالي" للانتقال من "ت" إلى "ث"، تقفز البطاقة 66px للأسفل فجأة
2. **حركة الأزرار**: شريط التنقل (السابق/التالي) ينزلق 67px للأسفل
3. **خروج من الشاشة**: navY=906 يعني أن شريط التنقل عند 1366×768 يكون **138px أسفل حافة الشاشة**
4. **عدم استقرار**: عند العودة من "ث" إلى "ت"، تقفز البطاقة 66px للأعلى

> **ملاحظة مهمة**: داخل نفس الحرف، التخطيط **ثابت تماماً** بين جميع الخطوات. المشكلة فقط عند **تبديل الحرف**.

## 2. السبب الجذري

### 2.1 سلسلة القيود

```
#content-zone (height: calc(100vh - header))
  └── #p4-container (height: 100%)
        ├── .p4-header                    ← ارتفاع ثابت
        ├── .p4-card-wrapper (flex: 1)    ← يأخذ ما تبقى
        │     └── .p4-card (grid: 1fr 1fr)
        │           ├── .p4-svg-zone      ← 319px ثابت (محتوى SVG)
        │           └── .p4-steps-panel   ← ⚠️ ارتفاع متغير حسب عدد الخطوات
        └── .p4-nav                       ← ارتفاع ثابت
```

### 2.2 لماذا يتغير الارتفاع

`.p4-card` يستخدم CSS Grid مع `1fr 1fr`. في Grid، ارتفاع الصف يُحدَّد بالعمود **الأطول**:

| الحالة | SVG zone | Steps panel | ارتفاع الصف (الأطول) |
|--------|----------|-------------|---------------------|
| 4 خطوات | 319px | 255px | **319px** (SVG يحكم) |
| 5 خطوات | 319px | 322px | **322px** (Steps تحكم) |

عند 4 خطوات: SVG zone (319px) أطول من steps panel (255px) → **SVG يتحكم بالارتفاع**.
عند 5 خطوات: steps panel (322px) أطول من SVG zone (319px) → **الخطوات تتحكم بالارتفاع**.

هذا التبديل في "من يحكم الارتفاع" هو السبب الجذري للقفزة.

### 2.3 لماذا يخرج Nav من الشاشة

`.p4-card-wrapper` لديه `flex: 1` مما يعني "خذ ما تبقى". لكن `.p4-card` داخله يتمدد حسب المحتوى (Grid implicit sizing). عندما محتوى البطاقة أكبر من المساحة المتبقية:
- البطاقة تتمدد خارج حدود `flex: 1`
- تدفع `.p4-nav` للأسفل
- Nav يخرج من viewport

## 4. الحلول المدروسة

### الحل A: تثبيت الحاوية على الحجم الأقصى (Max Content Size)

#### الفكرة:
حساب الارتفاع الأقصى (5 خطوات = حرف ث) واستخدامه كـ `min-height` ثابت لجميع الحروف.

#### التنفيذ المقترح:
```css
.p4-steps-panel {
  min-height: 322px;     /* = ارتفاع 5 خطوات المقاس */
  /* أو بوحدات نسبية: min-height: calc(5 * 3.5rem + 4 * var(--gap-sm)); */
}
```

#### التقييم:

| المعيار | التقييم | التفاصيل |
|---------|---------|----------|
| تجربة الطالب | ✅ ممتاز | لا قفزات — البطاقة ثابتة تماماً |
| تجربة المعلم | ✅ ممتاز | الأزرار في نفس المكان دائماً |
| شاشة البروجكتور | ⚠️ مقبول | مساحة فارغة مع حروف 4 خطوات (64px إضافية) |
| شاشات مختلفة | ⚠️ يحتاج اختبار | القيمة الثابتة بالبكسل قد لا تناسب كل الشاشات |
| RTL | ✅ لا تأثير | min-height لا علاقة له بالاتجاه |
| الصيانة | ⚠️ هشّ | إضافة درس بـ 6 خطوات تتطلب تحديث القيمة يدوياً |
| تعقيد التنفيذ | ✅ بسيط | سطر CSS واحد |

**المزايا**: أبسط حل. صفر قفزات.
**العيوب**: قيمة سحرية (magic number). مساحة فارغة مع 4 خطوات. هشّ أمام دروس مستقبلية.

### الحل B: حاوية مبنية على Viewport (Viewport-Based Container)

#### الفكرة:
بدل أن يتحكم المحتوى بالارتفاع، تتحكم الشاشة: تثبيت `.p4-card` بارتفاع محسوب من `vh`، والخطوات تتوزع داخله.

#### التنفيذ المقترح:
```css
.p4-card-wrapper {
  flex: 1;
  min-height: 0;        /* يسمح بالانكماش داخل flex */
  overflow: hidden;      /* يمنع التمدد خارج الحاوية */
}

.p4-card {
  height: 100%;          /* يملأ المساحة المتاحة */
  align-items: stretch;  /* العمودان يتمددان */
}

.p4-steps-panel {
  overflow-y: auto;      /* scroll إذا لزم */
  justify-content: center;
}
```

#### التقييم:

| المعيار | التقييم | التفاصيل |
|---------|---------|----------|
| تجربة الطالب | ✅ ممتاز | لا قفزات — كل شيء ثابت في viewport |
| تجربة المعلم | ✅ ممتاز | الأزرار ثابتة دائماً |
| شاشة البروجكتور | ✅ ممتاز | كل المحتوى يبقى داخل الشاشة |
| شاشات مختلفة | ✅ ممتاز | يتكيف تلقائياً مع أي حجم شاشة |
| RTL | ✅ لا تأثير | لا تغيير في الاتجاه |
| الصيانة | ✅ جيد | لا قيم سحرية — المحتوى يتكيف |
| تعقيد التنفيذ | ⚠️ متوسط | تغييرات في عدة قواعد + اختبار overflow |

**المزايا**: حل معماري نظيف. يضمن بقاء كل شيء في viewport. يتكيف مع أي شاشة.
**العيوب**: قد يحتاج scroll داخلي إذا كانت الشاشة صغيرة جداً (نادر في الفصول). يتطلب ضبط `overflow` بعناية.

### الحل C: نظام مُصغَّر/موسَّع مع قماشة ثابتة (Compact/Expanded + Fixed Canvas)

#### الفكرة:
تقسيم الخطوة إلى حالتين: **مصغّرة** (العنوان فقط، بدون وصف) و**موسّعة** (الخطوة النشطة فقط تعرض الوصف الكامل). مع تثبيت الحاوية الخارجية.

#### التنفيذ المقترح:
```css
/* الخطوات غير النشطة: مضغوطة */
.p4-step-item {
  min-height: 2rem;         /* label فقط */
  padding: 0.3rem 1rem;
}
.p4-step-item .p4-step-desc {
  display: none;             /* إخفاء الوصف */
}

/* الخطوة النشطة: موسّعة */
.p4-step-item.active:not(.done) {
  min-height: 4rem;
  padding: 0.6rem 1rem;
}
.p4-step-item.active:not(.done) .p4-step-desc {
  display: block;            /* إظهار الوصف */
}

/* الحاوية ثابتة */
.p4-card-wrapper {
  flex: 1;
  min-height: 0;
  overflow: hidden;
}
```

#### حساب الارتفاع المتوقع:

| الحالة | خطوات مصغّرة | خطوة موسّعة | الإجمالي التقريبي |
|--------|-------------|-------------|------------------|
| 4 خطوات، step 3 نشط | 3 × 32px = 96px | 1 × 64px = 64px | **160px + gaps** |
| 5 خطوات، step 5 نشط | 4 × 32px = 128px | 1 × 80px = 80px | **208px + gaps** |
| الفرق | | | **~48px** |

#### التقييم:

| المعيار | التقييم | التفاصيل |
|---------|---------|----------|
| تجربة الطالب | ⚠️ مقبول | الخطوات السابقة تفقد الوصف — أقل سياقاً |
| تجربة المعلم | ⚠️ مقبول | لا يرى الأوصاف السابقة كمرجع |
| شاشة البروجكتور | ✅ جيد | مساحة أكثر لمنطقة SVG |
| شاشات مختلفة | ✅ جيد | حجم أصغر يناسب شاشات أصغر |
| RTL | ✅ لا تأثير | لا علاقة بالاتجاه |
| الصيانة | ⚠️ معقد | حالات CSS إضافية (done, active, future) |
| تعقيد التنفيذ | ❌ عالي | تغييرات كبيرة في CSS + ربما JS |

**المزايا**: أقل مساحة إجمالية. الخطوة الحالية واضحة ومركّزة.
**العيوب**: فقدان سياق الخطوات السابقة. لا يزال هناك فرق ارتفاع (~48px) بين 4 و5 خطوات. تعقيد أعلى. يغيّر تجربة المستخدم بشكل جذري.

### الحل D: تثبيت معماري — Grid row ثابت + Flex داخلي (Recommended)

#### الفكرة:
المشكلة الجذرية أن Grid row يتبع العمود الأطول. الحل: **فصل ارتفاع البطاقة عن محتوى الخطوات** عبر جعل `.p4-card-wrapper` يتحكم بالارتفاع، و `.p4-steps-panel` تتكيف داخله.

#### التنفيذ المقترح:
```css
/* 1. منع card-wrapper من التمدد خارج flex allocation */
.p4-card-wrapper {
  flex: 1;
  min-height: 0;          /* ← مفتاح: يسمح للـ flex item بالانكماش */
  overflow: hidden;
}

/* 2. البطاقة تملأ المساحة المتاحة بدل أن تتمدد بالمحتوى */
.p4-card {
  height: 100%;
  align-content: stretch;
}

/* 3. لوحة الخطوات تتكيف داخل المساحة */
.p4-steps-panel {
  overflow-y: auto;         /* scroll احتياطي فقط */
  justify-content: center;  /* توزيع متساوٍ */
  max-height: 100%;
}

/* 4. SVG zone تتمدد لتملأ المساحة */
.p4-svg-zone {
  display: flex;
  align-items: center;
  justify-content: center;
}
```

#### كيف يعمل:

```
قبل (الحالي):
┌─ card-wrapper (flex:1, يتمدد بالمحتوى) ──────────┐
│ ┌─ card (grid, implicit height) ─────────────────┐ │
│ │ ┌─ svg ──┐ ┌─ steps ──────────────────────────┐│ │
│ │ │ 319px  │ │ 4 steps: 255px / 5 steps: 322px ││ │
│ │ └────────┘ └──────────────────────────────────┘│ │  ← ارتفاع يتغير!
│ └────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────┘
┌─ nav ─────────────────────────────────────────────┐  ← يتحرك!
└────────────────────────────────────────────────────┘

بعد (الحل D):
┌─ card-wrapper (flex:1, min-height:0, overflow:hidden) ┐
│ ┌─ card (height:100%) ──────────────────────────────┐ │
│ │ ┌─ svg ──┐ ┌─ steps (max-h:100%, overflow:auto) ┐│ │
│ │ │ center │ │ 4 steps: centered with gaps         ││ │
│ │ │   ↕    │ │ 5 steps: fills space or scrolls     ││ │  ← ارتفاع ثابت!
│ │ └────────┘ └─────────────────────────────────────┘│ │
│ └───────────────────────────────────────────────────┘ │
└───────────────────────────────────────────────────────┘
┌─ nav ────────────────────────────────────────────────┐  ← ثابت!
└──────────────────────────────────────────────────────┘
```

#### التقييم:

| المعيار | التقييم | التفاصيل |
|---------|---------|----------|
| تجربة الطالب | ✅ ممتاز | لا قفزات — البطاقة والأزرار ثابتة تماماً |
| تجربة المعلم | ✅ ممتاز | الأزرار في نفس المكان. شاشة مستقرة |
| شاشة البروجكتور | ✅ ممتاز | كل المحتوى يبقى داخل الشاشة المرئية |
| شاشات مختلفة | ✅ ممتاز | `flex:1` + `min-height:0` يتكيف مع أي حجم |
| RTL | ✅ لا تأثير | تغييرات في المحور العمودي فقط |
| الصيانة | ✅ ممتاز | لا قيم سحرية. يعمل مع أي عدد خطوات |
| تعقيد التنفيذ | ✅ بسيط | 4 قواعد CSS. لا تغيير في JS |

**المزايا**:
- **ثبات معماري**: الحاوية الخارجية تحدد الحجم، المحتوى يتكيف داخلها
- **لا قيم سحرية**: لا أرقام بكسل ثابتة تحتاج تحديث
- **مستقبلي**: يعمل مع 3 أو 6 أو 10 خطوات بدون تعديل
- **Nav ثابت**: شريط التنقل يبقى في مكانه دائماً داخل viewport

**العيوب**:
- مع شاشات صغيرة جداً + 5 خطوات، قد يظهر scroll داخلي (مقبول كحل احتياطي)
- مع 4 خطوات، ستكون هناك مساحة إضافية بين الخطوات (مقبول مع `justify-content: center`)

## 6. التوصية النهائية

### الحل D — تثبيت معماري عبر `min-height: 0` + `height: 100%`

#### لماذا هذا الحل:

1. **يعالج السبب الجذري**: بدل محاربة الأعراض (تثبيت ارتفاع، إخفاء محتوى)، يُصلح العلاقة بين الحاوية والمحتوى — الحاوية تحكم، المحتوى يتكيف.

2. **مبدأ `min-height: 0`**: هذا النمط المعروف في CSS Flexbox يسمح لـ flex item بالانكماش أقل من حجم محتواه. بدونه، `flex: 1` يعني "خذ المساحة المتبقية لكن لا تقل عن حجم المحتوى" — وهذا بالضبط ما يسبب تمدد البطاقة.

3. **مناسب للفصل الدراسي**:
   - المعلم يرى أزراراً ثابتة
   - الطلاب يرون بطاقة مستقرة
   - البروجكتور يعرض صورة ثابتة
   - لا يوجد "رقص" في العناصر عند تبديل الحروف

4. **مستقبلي**: إذا أُضيفت حروف بـ 6 أو 7 خطوات في دروس لاحقة، لا حاجة لتعديل CSS.

#### لماذا ليس الحلول الأخرى:

- **A (Max Size)**: يحل القفزة لكن لا يحل خروج Nav من الشاشة. قيم سحرية تتكسر مع دروس مستقبلية.
- **B (Viewport)**: متطابق تقريباً مع D لكن أقل وضوحاً في النية. D يوضح بدقة أين المشكلة (`min-height: 0`).
- **C (Compact/Expanded)**: يغيّر تجربة المستخدم جذرياً. لا يزال يعاني من فرق ارتفاع. تعقيد عالي بدون فائدة تناسبية.

## 7. خطة التنفيذ المقترحة

### المرحلة 1: تعديل CSS (4 قواعد فقط) — ✅ تم التنفيذ

| القاعدة | التغيير | السبب |
|---------|---------|-------|
| `.p4-card-wrapper` | إضافة `min-height: 0` | السماح بالانكماش داخل flex |
| `.p4-card-wrapper` | إضافة `overflow: hidden` | منع التمدد خارج الحاوية |
| `.p4-card` | إضافة `height: 100%` | ملء المساحة المتاحة بدل التمدد بالمحتوى |
| `.p4-steps-panel` | إضافة `max-height: 100%` + `overflow-y: auto` | منع الخطوات من تمديد البطاقة |

**التنفيذ الفعلي (css/style.css):**
- `.p4-card-wrapper`: `min-height: 0` + `overflow: hidden` + `display: flex; align-items: stretch`
- `.p4-card`: `grid-template-rows: minmax(0, 1fr)` (يثبّت ارتفاع الصف بدل اتباع العمود الأطول) + `height: 100%; min-height: 0`
- `.p4-svg-zone`: `min-height: 0; overflow: hidden` + `display: flex; align-items: center; justify-content: center`
- `.p4-steps-panel`: `gap: calc(var(--gap-sm) - 2px)` (احتواء 5 خطوات + نص 81 حرفاً بلا فيض) + `min-height: 0; max-height: 100%` + `overflow-x: hidden; overflow-y: auto`
- Media query `@media (max-width: 900px)`: إلغاء التثبيت للشاشات غير الصفية (`.p4-card` → `grid-template-rows: auto auto; height: auto`، `.p4-card-wrapper` → `overflow: visible`)

### المرحلة 2: الاختبار — ✅ تم التحقق (1366×768)

| الاختبار | الشرط | النتيجة |
|----------|-------|---------|
| ب (4 خطوات) @ 1366×768 | Nav مرئي. بطاقة ثابتة. كل الخطوات مقروءة | ✅ cardH=433، navTop=645 |
| ث (5 خطوات) @ 1366×768 | نفس ارتفاع البطاقة كـ "ب". Nav في نفس الموقع | ✅ cardH=433، stepsScroll=no |
