## 1. Current P6 Architecture

### كيف تعمل P6 حالياً

P6 "التمييز السمعي" (80–100 دقيقة) هي مرحلة تدريب سمعي يقودها المعلم: يشغّل المعلم صوتاً،
يستمع الطلاب، يستجيبون (أصابع/إبهام/إصغاء)، ثم يكشف المعلم الإجابة على الشاشة عبر Space.

التسلسل التشغيلي لكل سؤال:
1. `initP6()` يصفّر الحالة ويحقن `#p6-container` داخل `#content-zone`.
2. `renderP6()` يبني: رأس (تبويبات الجولات + تعليمات الجولة) ← عداد السؤال ← منطقة التفاعل ← منطقة الإجابة (مخفية) ← زر "كشف الإجابة".
3. المعلم يشغّل الصوت (زر داخل منطقة التفاعل) ← الطلاب يستجيبون.
4. `advanceP6()` أول ضغطة Space = إظهار منطقة الإجابة (class `visible`) وتحويل الزر إلى "التالي".
5. `advanceP6()` ثاني ضغطة Space = السؤال التالي في الجولة، أو الجولة التالية، أو عند نهاية D3 → `goToPhase(6)` (P7).

### دوال JavaScript المستخدمة (مرجع الأسطر في `js/app.js`)

| الدالة | السطر | المسؤولية |
|---|---|---|
| `initP6` | 1297 | إعادة ضبط الحالة + حقن الحاوية + render + PhaseTimer |
| `advanceP6` | 1308 | كشف الإجابة ← تقدم سؤال ← تقدم جولة ← P7 |
| `getCurrentP6Round` | 1334 | جلب كائن الجولة من `discriminationRounds` حسب `roundOrder` |
| `renderP6` | 1340 | بناء كامل واجهة السؤال (أنواع الجولات الثلاثة) + `updateHint` |
| `p6GoRound` | 1436 | قفز مباشر إلى جولة محددة |
| `p3PlaySound` | 803 | تشغيل صوت حرف عبر `AudioManager.playLetter` (يُستدعى من أزرار P6) |
| `retreat` | 283–290 | التراجع: إخفاء الإجابة ثم سؤال سابق (case P6) |

### حالة STATE المرتبطة

```
p6RoundIndex     → الجولة الحالية (فهرس في roundOrder: D1/D2/D3)
p6PairIndex      → السؤال الحالي داخل الجولة
p6AnswerVisible  → هل الإجابة ظاهرة؟
```

### أنواع الجولات (من `LESSON_01.discriminationRounds`)

- **D1 — identify (عدّ الأصابع):** 8 أسئلة. كل سؤال `{ playId, answer }`. يعرض زر تشغيل دائري كبير
  وسؤال "كم إصبعاً؟"؛ الإجابة: الحرف + عدد الأصابع + الاسم.
- **D2 — sameordiff (نفس أم مختلف):** 6 أسئلة. كل سؤال `{ playIds[2], same }`. يعرض بطاقتي صوت +
  فاصل "؟" وسؤال "نفس أم مختلف؟"؛ الإجابة: شارة "= نفس الصوت" أو "≠ صوتان مختلفان" + الحرفان.
- **D3 — close (الأصوات المتقاربة):** سؤالان. كل سؤال `{ ids[3], note }`. يعرض 3 بطاقات حروف
  (ب/ت/ث أو ب/ن) وسؤال "استمع إلى الأصوات المتقاربة"؛ الإجابة: صندوق ملاحظة.
- ترتيب الجولات من `LESSON_01.phases` (P6): `roundOrder: ['D1','D2','D3']` — **جولتان فقط في D3**.

## 2. Pedagogical Alignment Review

| المبدأ | الحالة الحالية | التقييم |
|---|---|---|
| **الاستماع قبل الإجابة** | زر الصوت منفصل، والإجابة مخفية حتى يضغط المعلم Space | ✅ مطابق — الفلسفة السمعية محفوظة |
| **المعلم Controller** | لا تشغيل تلقائي؛ كل خطوة (صوت/كشف/تقدم) بضغطة المعلم | ✅ مطابق |
| **Projector-first** | أحجام `clamp()` كبيرة، تباين عالٍ، ترميز لوني ثابت | ⚠️ يطابق جزئياً — بعض العناصر صغيرة (انظر القسم 3) |
| **Progressive Reveal** | الإجابة لا تظهر إلا بعد الاستماع؛ خطوة واحدة لكل Space | ✅ مطابق، لكن الكشف دفعة واحدة (الحرف+الأصابع+الاسم معاً) |
| **الانتباه كمورد محدود** | عناصر الشاشة قليلة؛ العداد شارة صغيرة ذهبية؛ التبويبات تبقى ظاهرة | ⚠️ جيد عموماً، مع ملاحظات على ضجيج التبويبات الثابتة ونسخ موجهة للمعلم على مسرح الطلاب |

**ما يحتاج تحسين:**
1. **الكشف دفعة واحدة في D1**: عند الكشف تظهر الحرف + عدد الأصابع + الاسم معاً في انفجار معلومات.
   الترتيب الطبيعي للمعلم: يسمع الطلاب → الطلاب يرفعون الأصابع → المعلم يكشف "ب / باء / صوت واحد".
2. **نسخ موجهة للمعلم تظهر للطلاب**: نص "لوحة النتيجة — اكشف الإجابة بعد الاستماع" في مكان الإجابة،
   و"استمع ثم قارن" قبل البطاقات — هذه توجيهات مدرّس على مسرح موجه للطلاب (مقبول لكن قابل للتحسين).
3. **حالة الاستماع غير مرئية**: عند تشغيل الصوت لا يوجد مؤشر "جارٍ التشغيل" على زر التشغيل نفسه
   (مؤشر `.audio-indicator` غير موجود في أزرار P6) — الطلاب لا يعرفون أن الصوت انتهى.
4. **توزيع الجولات غير متوازن**: D1 = 8 أسئلة، D2 = 6، D3 = 2 فقط. D3 الأقصر قد يبدو مقتضباً مقابل
   ثقل D1 رغم أن D3 هو أخطرها تربوياً (ب ت ث المشتركة في الجسم).

## 3. Visual Classroom Analysis

(تحليل فقط — لا حلول CSS)

### توزيع العناصر

- الحاوية `.p6-container` بعرض أقصى 1080px وبعمود مرن، داخل `#content-zone` (الذي هو `overflow: hidden`
  وغير قابل للتمرير) — الصفحة الكلية `grid-template-rows: auto 1fr auto auto` (HUD / محتوى / أزرار / تقدم).
- المسرح `.p6-main` شبكة بعمودين لكن **كل العناصر تمتد `grid-column: 1/-1`** فتصبح فعلياً عموداً واحداً
  محورياً بعرض أقصى 860px. النتيجة: **فراغات جانبية كبيرة** على الشاشات الواسعة (1920×1080).
- المساحة الرأسية: تعليمات + عداد + منطقة تفاعل + منطقة إجابة + زر تحكم — كلها مكدسة في عمود واحد،
  مع `align-content: center` فتتجمع في المنتصف وتترك فراغاً أعلى/أسفل حسب ارتفاع الشاشة.

### حجم البطاقات

- زر التشغيل الكبير (D1): دائرة `clamp(15rem,33vw,20rem)` عرضاً و`clamp(5.5rem,14vh,8rem)` ارتفاعاً — ممتاز.
- بطاقتا D2: `clamp(10.25rem,21vw,13.5rem)` × `clamp(5.5rem,11vh,6.75rem)` — جيد.
- بطاقات D3: بحد أدنى 100px فقط — أصغر نسبياً من بطاقات D2 رغم أهمية المحتوى (أصوات متقاربة).
- **عناصر نصية صغيرة**: تبويبات الجولات `--fs-xs`، العداد `--fs-xs`، اسم الحرف في الإجابة `--fs-sm` —
  هذه قد تكون صعبة القراءة من الصفوف الخلفية (المبدأ: كل عنصر على الشاشة يجب أن يُقرأ من الخلف).

### المساحات الفارغة

- الفراغ الجانبي (بعرض 860px داخل شاشة 1920) واضح ومؤثر بصرياً على التمركز.
- الفجوات بين العناصر مضبوطة بـ `clamp` لكنها ضيقة نسبياً (تصميم مضغوط من Phase 1).

### التسلسل البصري

- القراءة من أعلى لأسفل: تبويبات ← تعليمات ← عداد ← منطقة تفاعل ← إجابة ← زر — منطقي.
- **التبويبات الثلاثة تظهر دائماً** حتى أثناء السؤال، والتبويب النشط مملوء بالذهب (أعلى تباين في الشاشة)
  — يبدو أنه قد ينافس السؤال على الانتباه.
- زر "كشف الإجابة" (شفاف بحدود ذهبية) ثم "التالي" (فيروزي مصمت) — تمييز جيد بحالة عبر `hidden`.

### وضوح النشاط للطلاب من الخلف

- الرسالة الأساسية (ماذا أسمع؟ كم إصبعاً؟ نفس أم مختلف؟) كبيرة وواضحة.
- الإجابة بعد الكشف كبيرة (حرف `clamp(2.6rem,7vh,5rem)` + أصابع بلون ذهبي).
- **ملاحظات الوضوح**: صغر بعض العناصر (التبويبات/العداد/الاسم)، عدم وجود مؤشر "جارٍ التشغيل" على
  زر الصوت، واعتماد أيقونات رموز تعبيرية (🔊) التي يختلف مظهرها حسب خط الجهاز.

## 5. Redesign Goals

الهدف ليس "تصغير الصفحة" بل تحويل P6 إلى **"Auditory Training Classroom Stage"** — مسرح تدريب سمعي
واضح وبطل واحد لكل لحظة، مع الحفاظ على المبادئ الحاكمة.

### أهداف التصميم الجديد

1. **المسرح السمعي**: التركيز على "الاستماع أولاً" — زر الصوت هو بطل اللحظة، والإجابة تأتي بعد الاستماع فقط.
2. **تسلسل بصري واحد**: قراءة واضحة من أعلى لأسفل لكل سؤال (تعليمات → استمع → استجب → اكشف) دون منافسة بصرية.
3. **استغلال المساحة**: إعادة توزيع المسرح ليملأ ارتفاع/عرض `#content-zone` بثقة دون فراغات ميتة، مع بقاء عدم وجود Scroll.
4. **وضوح البروجكتور**: كل عنصر يُقرأ من الصفوف الخلفية — رفع حد أدنى لأحجام النصوص والأزرار ذات الأهمية،
   وإبراز حالة "جارٍ التشغيل" على زر الصوت.
5. **الكشف التدريجي المحسّن**: إبقاء خطوة واحدة لكل Space مع كشف أنظف (لا انفجار معلومات).
6. **عدم تغيير البيانات أو الصوت أو التنقل**: `lesson-01.js` و`AudioManager` ومنطق التنقل لا تُمس.

### ما لن يتغير

- ترتيب الجولات ومنطقها (D1→D2→D3) والحالات الثلاث في STATE.
- آلية الصوت (MP3 + Web Speech عبر AudioManager).
- اختصارات لوحة المفاتيح وعقد DOM المعتمدة في `app.js`.

## 7. Implementation Roadmap

(مقترح لمستقبل — لا تنفيذ الآن)

### Phase 1 — Visual Structure
الهدف: بناء "المسرح" — إعادة توزيع `.p6-container`/`.p6-main` لملء `#content-zone` بعمق،
تحسين التسلسل الرأسي، معالجة الفراغات الجانبية، رفع الحد الأدنى لأحجام العناصر المهمة.
(CSS فقط — لا مساس بالمنطق.)

### Phase 2 — Interaction Polish
الهدف: صقل التفاعل — حالة "جارٍ التشغيل" على أزرار الصوت أثناء النطق، انتقال أنظف لكشف الإجابة،
توازن حجم بطاقات D3 مع D2، تهدئة التبويبات (أقل منافسة بصرية). (CSS + تعديلات `app.js` محدودة).

### Phase 3 — Teacher Guidance
الهدف: إرشاد المعلم — فصل "نسخ المعلم" عن "نسخ الطلاب" (التلميحات واللوحات التوجيهية)،
تحسين نصوص `updateHint` لمرافقة كل خطوة، ضبط العداد والتبويبات ليخدما المعلم دون إرباك الطلاب.
(تعديلات نصوص وCSS بسيطة.)

> كل Phase قادمة تُنفَّذ عبر `PHASE_PROTOCOL.md` وتُختبر على 1280×720 / 1366×768 / 1920×1080
> مع التحقق من: عدم كسر لوحة المفاتيح، عدم كسر الصوت، عدم كسر التنقل، عدم تغيير البيانات، عدم Scroll.
