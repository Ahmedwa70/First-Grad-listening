## 1. المشكلة

عند دخول P2 (الصوت أولاً)، يظهر الشريط العلوي كاملاً:

```
—   اختر صوتاً   🔊
```

أيقونة مكبر الصوت مرئية **قبل** أن يختار الطالب أي صوت. هذا يتعارض مع فلسفتين:

1. **الكشف التدريجي** (DESIGN_PHILOSOPHY.md §5): "لا يُعرض كل شيء دفعة واحدة"
2. **التسلسل المنطقي**: المكبر أداة تشغيل — لا معنى لوجوده قبل وجود صوت مختار

### السلوك المطلوب

| الحالة | ما يظهر | ما لا يظهر |
|--------|---------|-----------|
| **أولية** (لا حرف مختار) | "اختر صوتاً" (pill) | أيقونة المكبر، اسم الحرف |
| **بعد الاختيار** | 🔊 + `/b/` (pill) + باء | "اختر صوتاً" (يُستبدل بالفونيم) |

## 2. التحليل — لماذا السلوك الحالي غير مناسب تربوياً

### 2.1 مبدأ الكشف التدريجي

المشروع يعتمد على كشف العناصر عند الحاجة (P1: كل Space يكشف block، P3: كل خطوة تكشف جزءاً من الحرف). في P2، عرض المكبر قبل الاختيار يكسر هذا النمط — الأداة موجودة قبل أن يكون لها وظيفة.

### 2.2 انتباه الطالب

في الحالة الأولية، الطالب يجب أن يفهم أن المطلوب هو **اختيار صوت من البطاقات**. وجود المكبر يشتت — هل يجب الضغط عليه؟ الـ pill وحدها ("اختر صوتاً") تعطي تعليمة واضحة بدون عناصر مربكة.

### 2.3 الاتساق مع واجهات التعليم

أنظمة مثل Duolingo و Quizlet لا تعرض أدوات التشغيل قبل وجود محتوى للتشغيل.

## 3. تحليل الكود — نقاط التحكم

### 3.1 مسار البيانات

```
initP2()
  └── STATE.p2ActiveLetter = null     ← لا حرف مختار
  └── buildP2HTML()                    ← ينشئ DOM كاملاً (أيقونة + "اختر صوتاً" + "—")

p2SelectLetter(letterId)
  └── STATE.p2ActiveLetter = letterId  ← حرف مختار
  └── .sound-btn.active toggle         ← CSS class على البطاقة
  └── phonemeEl.textContent = phoneme  ← "/b/"
  └── nameEl.textContent = name        ← "باء"
  └── p2PlaySound()                    ← تشغيل الصوت
```

### 3.2 نقطة التحكم المختارة

**CSS `:has()` على `.p2-container`** — نفس النمط المستخدم بالفعل لتلوين الفونيم (style.css أسطر 950-973).

| الخيار | المزايا | العيوب | الحكم |
|--------|---------|--------|-------|
| **CSS `:has()`** | لا JS، لا HTML، يستخدم نمطاً موجوداً | — | ✅ **الأفضل** |
| JS class toggle | مرن | يحتاج تعديل `initP2` + `p2SelectLetter` | ❌ تعقيد غير مبرر |
| HTML مشروط | تحكم كامل | يحتاج تعديل `buildP2HTML` | ❌ يكسر بنية HTML |

### 3.3 لماذا CSS كافٍ

`p2SelectLetter()` يضيف بالفعل class `active` على `.sound-btn`. CSS يكتشف وجود/غياب `.sound-btn.active` عبر `:has()` — لا حاجة لأي تعديل في JS.

## 4. القرار — الحل المعماري

### 4.1 القواعد المضافة

```css
/* حالة المسرح الصوتي — قبل اختيار الصوت */
.p2-container:not(:has(.sound-btn.active)) .speaker-icon,
.p2-container:not(:has(.sound-btn.active)) .active-letter-name {
  display: none;
}
```

### 4.2 منع Layout Shift

مشكلة مكتشفة: على دقات > 768px ارتفاع، الأيقونة (`10vh`) أطول من phoneme pill — ظهورها يزيد ارتفاع `.p2-top`.

**الحل**: `min-height` على `.speaker-zone` بنفس قيمة الأيقونة:

```css
.speaker-zone {
  min-height: clamp(48px, 10vh, 96px);
}
```

هذا يحجز مساحة الأيقونة حتى عندما تكون مخفية → ارتفاع ثابت في كلا الحالتين.

### 4.3 لماذا `display: none` وليس `visibility: hidden`

- `visibility: hidden` يُبقي الأيقونة تحتل مساحة أفقية → فراغ مرئي بجانب pill
- `display: none` يزيل الأيقونة بالكامل → pill وحدها في المنتصف (أنظف)
- `min-height` يمنع التغيير العمودي → أفضل ما في الحلين
