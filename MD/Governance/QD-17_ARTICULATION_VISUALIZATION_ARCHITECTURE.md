## 1. Educational Problem — المشكلة التعليمية

### 1.1 ما المشكلة؟

الطالب الصيني المبتدئ (A0) يواجه أصواتاً عربية **لا وجود لها** في أي لغة يعرفها. النظام الحالي يقدم:

```
الصوت (MP3) → الفونيم (/ث/) → الحرف (ث) → الكلمة (ثوب)
```

لكنه لا يقدم **كيف يُنتَج الصوت جسدياً**. الطالب يسمع الصوت ويرى الرمز — لكنه لا يعرف:
- أين يضع لسانه
- كيف يحرك شفتيه
- من أين يخرج الهواء
- ما الفرق الحركي بين ت و ث

هذه فجوة بين **الإدراك السمعي** و**الإنتاج الحركي** — وهي الفجوة الأصعب في تعلم أصوات اللغة الثانية.

### 1.2 الأدلة من الوثائق التأسيسية

| المصدر | ما يقوله | المرتبة |
|--------|---------|---------|
| **Doc 07** (Implementation Map) | "رسوم متحركة للفم" + `mouth_th_1.svg, mouth_th_2.svg, mouth_th_3.svg` | مرتبة 1 (أعلى مرجعية) |
| **Doc 07** | "صور تسلسلية لحركة اللسان" + "شاشة تعليم النطق. رسوم الفم مرئية." | مرتبة 1 |

| **Doc 04** (Instructional Blueprint) | نشاط 2.4: "يُخرج لسانه برفق بين أسنانه وينفخ هواءً" | مرتبة 4 |
| **Doc 04** | "صوت مع رسوم متحركة للفم — الطالب يُنشّط الكاميرا للمقارنة الذاتية" | مرتبة 4 |

**الخلاصة**: هذه ليست طبقة جديدة مُقترحة — هي **متطلب موثّق في أعلى مرجعية** (Doc 07) لم يُنفَّذ بعد.

### 1.3 ما المشكلات التي تحلها؟

| # | المشكلة | كيف تحلها Articulation Visualization |
|---|---------|--------------------------------------|
| 1 | **تعريف مكان خروج الصوت** | رسم يُظهر أين يلمس اللسان (لثة؟ أسنان؟ حلق؟) |
| 2 | **تصحيح النطق** | مقارنة بصرية: "لسانك هنا" vs "يجب أن يكون هنا" |
| 3 | **مساعدة الذاكرة** | ربط الصوت بصورة حركية → ذاكرة متعددة القنوات |
| 4 | **تقليل الخلط** | ت vs ث: نفس الصوت تقريباً — الفرق في اللسان |
| 5 | **تدريب التقليد** | الطالب يرى الحركة → يقلدها → يُنتج الصوت |
| 6 | **سد الفجوة بين السمع والإنتاج** | الأذن تسمع، العين ترى الحركة، الجسم يقلد |

### 1.4 موقعها في مسار التعلم

```
الصوت (سمعي)
    ↓
التمييز السمعي (هل هذا ت أم ث؟)
    ↓
━━━ Articulation Visualization تدخل هنا ━━━
    ↓
التقليد الحركي (أضع لساني هنا وأنفخ)
    ↓
النطق (إنتاج الصوت)
    ↓
الحرف (ربط الصوت بالشكل المكتوب)
```

الطبقة تملأ الفراغ بين **"سمعت الصوت"** و**"أستطيع إنتاجه"** — وهي الخطوة التي تفشل بدون توجيه حركي بصري.

## 4. Sound Classification — تصنيف الأصوات العربية الـ 28

### 4.1 التصنيف حسب مكان النطق (Place of Articulation)

| المجموعة | مكان النطق | الحروف | عدد | المكون البصري الرئيسي |
|---------|-----------|--------|-----|---------------------|
| **شفوية** (Bilabial) | الشفتان | ب، م | 2 | شفتان مغلقتان → مفتوحتان |
| **شفوية-سنية** (Labiodental) | الشفة + الأسنان | ف | 1 | الشفة السفلى + الأسنان العليا |
| **بين-أسنانية** (Interdental) | اللسان بين الأسنان | ث، ذ، ظ | 3 | اللسان بارز بين الأسنان |
| **لثوية** (Alveolar) | طرف اللسان + اللثة | ت، د، ط، ض، ن، ل، ر، س، ز، ص | 10 | طرف اللسان على/قرب اللثة |
| **غارية** (Palatal) | وسط اللسان + الغار | ش، ي، ج | 3 | وسط اللسان مرتفع |
| **طبقية** (Velar) | مؤخر اللسان + الطبق | ك | 1 | مؤخر اللسان يلمس الطبق |
| **لهوية** (Uvular) | مؤخر اللسان + اللهاة | ق، غ، خ | 3 | مؤخر اللسان + اللهاة |
| **بلعومية** (Pharyngeal) | جذر اللسان + البلعوم | ع، ح | 2 | تضييق البلعوم |
| **حنجرية** (Glottal) | الحنجرة | ء، هـ | 2 | الأوتار الصوتية |
| **أنفية** (Nasal) | الأنف + اللثة/الشفتين | ن، م | (مذكور أعلاه) | الهواء من الأنف |

### 4.2 التصنيف حسب صعوبة النطق للمتعلم غير العربي

| الفئة | الحروف | السبب | الحاجة لـ Articulation |
|-------|--------|-------|----------------------|
| **حاسم — أصوات غائبة تماماً** | ع، ح، خ، غ، ق، ص، ض، ط، ظ، ث، ذ | لا مقابل في الصينية أو الإنجليزية أو معظم اللغات | 🔴 **ضروري** |
| **مهم — أصوات موجودة لكن مختلفة** | ر، هـ، ء | موجودة بشكل مختلف | 🟡 **مفيد** |
| **اختياري — أصوات مشابهة** | ب، ت، د، ن، م، ل، س، ز، ش، ف، ك، ج، ي، و | مقابلات قريبة في لغات أخرى | ⚪ **اختياري** |

### 4.3 عدد النماذج المطلوبة

**السؤال**: هل نحتاج 28 رسمة أم أقل؟

| مكان النطق | عدد الحروف | عدد النماذج البصرية المميزة | السبب |
|-----------|-----------|---------------------------|-------|
| شفوية | 2 | **1** | ب وم — نفس حركة الشفتين، الفرق أنفي فقط |
| شفوية-سنية | 1 | **1** | ف — فريد |
| بين-أسنانية | 3 | **1** | ث وذ وظ — نفس موضع اللسان، الفرق في الجهر/التفخيم |
| لثوية | 10 | **3** | (1) انفجارية ت/د/ط/ض (2) احتكاكية س/ز/ص (3) جانبية/تكرارية ل/ر/ن |
| غارية | 3 | **1** | ش/ج/ي — نفس المنطقة |
| طبقية | 1 | **1** | ك — فريد |
| لهوية | 3 | **1** | ق/غ/خ — نفس المنطقة |
| بلعومية | 2 | **1** | ع/ح — نفس المنطقة |
| حنجرية | 2 | **1** | ء/هـ — نفس المنطقة |
| **المجموع** | **28** | **11 نموذج أساسي** | |

**11 نموذجاً أساسياً** يغطي 28 حرفاً. كل نموذج يُعاد استخدامه مع تعديلات طفيفة (جهر/همس، تفخيم/ترقيق، أنفي/فموي).

## 5. Architecture Design — تصميم المعمارية

### 5.1 تقييم الخيارات الثلاثة

#### الخيار A: ملف SVG منفصل لكل حرف (28 ملف)

| الجانب | التقييم |
|--------|---------|
| الدقة التعليمية | ✅ كل حرف له رسمة مخصصة |
| الصيانة | ❌ 28 ملف × تحديث = عبء كبير |
| الاتساق البصري | ❌ صعب ضمان اتساق 28 رسمة |
| حجم الملفات | ⚠️ 28 SVG × ~5KB = ~140KB |
| الوقت لاحقاً | ❌ كل محاضرة تحتاج تصميم ملفات جديدة |

#### الخيار B: نظام مكونات قابل لإعادة الاستخدام

| الجانب | التقييم |
|--------|---------|
| الدقة التعليمية | ⚠️ يحتاج تصميماً دقيقاً للمكونات |
| الصيانة | ✅ 11 نموذج بدل 28 ملف |
| الاتساق البصري | ✅ مكونات موحدة = اتساق تلقائي |
| حجم الملفات | ✅ ~11 نموذج × ~5KB = ~55KB |
| القابلية للتوسع | ✅ مكونات يُعاد تركيبها |
| التعقيد التقني | ❌ يحتاج محرك تركيب مكونات |

#### الخيار C: Hybrid System (الموصى به)

| الجانب | التقييم |
|--------|---------|
| الدقة التعليمية | ✅ نماذج أساسية + تخصيصات |
| الصيانة | ✅ 11 نموذج + تخصيص بالبيانات |
| الاتساق البصري | ✅ نماذج موحدة مع اختلافات محددة |
| حجم الملفات | ✅ أصغر حجم |
| القابلية للتوسع | ✅ نموذج جديد فقط عند مكان نطق جديد |
| التعقيد | ⚠️ متوسط — بيانات في lesson-XX.js + نماذج SVG |

### 5.2 القرار المعماري: Hybrid System (الخيار C)

**البنية**:

```
11 نموذج SVG أساسي (حسب مكان النطق)
    ×
بيانات التخصيص في lesson-XX.js (جهر/همس، تفخيم، أنفي)
    =
28+ تمثيل فريد
```

**المبدأ**: النموذج يُظهر **مكان** النطق. البيانات تحدد **كيفية** النطق (الخصائص الصوتية).

**مثال**: نموذج "بين-أسنانية" واحد يخدم:
- ث (مهموس، مرقق) — اللسان بين الأسنان + سهم هواء
- ذ (مجهور، مرقق) — نفس الموضع + اهتزاز الأوتار (لون مختلف)
- ظ (مجهور، مفخّم) — نفس الموضع + تفخيم اللسان (شكل مختلف)

## 6. Technology Evaluation — تقييم تقنيات التمثيل

### 6.1 مقارنة شاملة

| **التوافق مع DATA-ENGINE-VIEW** | ✅ | ✅ | ⚠️ يحتاج مكتبة خارجية | ✅ | ❌ لا يتوافق | ✅ |

### 6.2 استبعاد الخيارات

| الخيار | سبب الاستبعاد |
|--------|-------------|
| **C: Lottie** | يحتاج مكتبة خارجية (~50KB) — يتعارض مع Offline-first ولا CDN |
| **E: Short Video** | حجم كبير (500KB+ لكل حرف × 28 = 14MB+)، صعب التحكم بالخطوات، لا يتوافق مع الكشف التدريجي |
| **D: CSS Animation** | محدودة الأشكال — لا تستطيع رسم لسان/أسنان/حلق بدقة كافية |
| **A: SVG ثابت** | لا يُظهر حركة اللسان — Doc 07 يطلب "صور تسلسلية" و"رسوم متحركة" |

### 6.3 القرار: **F — Hybrid (SVG + CSS Animation)**

**المبرر**:
1. SVG يرسم التشريح بدقة (لسان، أسنان، شفتين، حلق، مجرى هواء)
2. CSS يحرّك العناصر (انزلاق اللسان، فتح الشفتين، تدفق الهواء)
3. لا مكتبات خارجية — Offline-first كامل
4. حجم صغير (~5-15KB لكل نموذج)
5. تحكم كامل من المعلم (Space = خطوة تالية)
6. يتوافق مع DATA-ENGINE-VIEW
7. يعمل على البروجكتور بأي دقة (vector)

**المبدأ التقني**:
- SVG يحتوي العناصر التشريحية كـ `<g>` مجموعات (`tongue`, `teeth`, `lips`, `airflow`, `palate`)
- CSS classes تتحكم بالحالة: `.tongue-interdental`, `.tongue-alveolar`, `.lips-closed`, `.airflow-active`
- JavaScript (في app.js) يُضيف/يزيل CSS classes حسب خطوة الكشف التدريجي

```javascript
      { id: 'tongue',  label: 'موضع اللسان',   css: 'art-tongue-out' },
      { id: 'airflow', label: 'تدفق الهواء',   css: 'art-airflow' },
      { id: 'sound',   label: 'إنتاج الصوت',   css: 'art-vibrate' }
    ]
  }
}
```

### 7.2 شرح الحقول

| الحقل | النوع | الغرض |
|-------|-------|-------|
| `place` | string | مكان النطق — مفتاح اختيار النموذج SVG |
| `manner` | string | طريقة النطق (stop/fricative/nasal/lateral/trill) |
| `voicing` | string | الجهر (voiced/voiceless) |
| `emphasis` | boolean | التفخيم (للحروف المفخمة: ص/ض/ط/ظ) |
| `nasality` | boolean | الأنفية (للحروف الأنفية: م/ن) |
| `template` | string | اسم ملف SVG النموذجي (`interdental.svg`) |
| `difficulty` | string | critical/important/optional — يحدد أولوية العرض |
| `slowAudio` | string | ملف صوت بطيء للتدريب الحركي |
| `description` | object | وصف نصي متعدد اللغات لكيفية النطق |
| `steps` | array | خطوات الكشف التدريجي مع CSS class لكل خطوة |

### 7.3 التوافق مع DATA - ENGINE - VIEW

```
DATA (lesson-XX.js)          ENGINE (app.js)              VIEW (HTML + CSS)
─────────────────            ──────────────               ─────────────────
letter.articulation    →     renderArticulation(letter)  → <div class="art-viewer">
  .template            →       loadTemplate(template)    →   <svg> (نموذج تشريحي)
  .steps               →       progressiveReveal(steps)  →     <g class="tongue art-tongue-out">
  .description         →       showDescription(lang)     →   <p class="art-desc">
  .slowAudio           →       AudioManager.play(slow)   →   (صوت)
```

**لا تغيير في بنية DATA-ENGINE-VIEW** — إضافة بيانات جديدة + دوال جديدة + CSS جديد.

## 9. Global Learner Analysis — التصميم للمنصة الدولية

### 9.1 تحليل حسب خلفية المتعلم

| الخلفية | الأصوات الصعبة | ما يحتاجه من Articulation |
|---------|--------------|--------------------------|
| **صيني (الأساسي الآن)** | ث/ذ (بين-أسنانية)، ع/ح (بلعومية)، غ/خ (لهوية)، ص/ض/ط/ظ (مفخمة)، ر (تكرارية) | كل النماذج — معظم الأصوات غائبة |
| **إنجليزي** | ع/ح (بلعومية)، غ/خ/ق (لهوية)، ص/ض/ط/ظ (مفخمة) | نماذج البلعوم واللهاة والتفخيم |
| **أوروبي (فرنسي/ألماني)** | ع/ح (بلعومية)، ث/ذ (بين-أسنانية — بعض اللغات)، ص/ض/ط/ظ (مفخمة) | مشابه للإنجليزي + بين-أسنانية |
| **تركي/فارسي/أوردو** | ع/ح (جزئياً)، ص/ض/ط/ظ (جزئياً — موجودة لكن مختلفة) | تفاصيل الفرق — ليس التعريف من الصفر |
| **نظام غير لاتيني (ياباني/كوري)** | مشابه للصيني مع فروق في ر ول | نفس النماذج تقريباً |

### 9.2 طبقات العرض حسب اللغة

```
الطبقة الأولى: الرسم التشريحي (SVG)
    ← عالمي — لا يتغير حسب اللغة

الطبقة الثانية: الوصف النصي
    ← متعدد اللغات: ar + zh + en (حالياً)
    ← يُضاف حسب الحاجة: fr, tr, ja, ko...

الطبقة الثالثة: المقارنة باللغة الأم (L1 Bridge)
    ← "هذا الصوت مثل th في think" (للإنجليزي)
    ← "هذا الصوت غير موجود في الصينية" (للصيني)
    ← "هذا الصوت مثل ث في فارسي" (للفارسي)

الطبقة الرابعة: IPA المرجعي
    ← عالمي — /θ/ لكل اللغات
```

### 9.3 التصميم للتوسع

نموذج البيانات المقترح (القسم 7) يدعم التوسع تلقائياً:
- `description` = كائن متعدد اللغات — أضف مفتاحاً جديداً لكل لغة
- `template` = نموذج SVG — لا يتغير حسب اللغة
- `steps` = خطوات الكشف — لا تتغير حسب اللغة
- الرسم التشريحي **عالمي** — الفم البشري واحد

## 11. Final Decision — القرار النهائي

### 11.1 النظام الأفضل للمشروع

**Hybrid SVG + CSS Animation System**

مع:
- 11 نموذج SVG أساسي (حسب مكان النطق)
- بيانات تخصيص في `lesson-XX.js` (حقل `articulation`)
- CSS classes للتحكم بالحالة والحركة
- كشف تدريجي بتحكم المعلم (Space)
- وصف متعدد اللغات

### 11.2 لماذا هذا النظام؟

1. **يحل فجوة موثّقة**: Doc 07 يطلب "رسوم متحركة للفم" — هذا النظام ينفذها
2. **يتوافق مع DATA-ENGINE-VIEW**: بيانات في JS، منطق في app.js، عرض في SVG+CSS
3. **Offline-first**: لا مكتبات خارجية، لا CDN، كل شيء محلي
4. **Projector-first**: SVG vector = واضح بأي دقة
5. **Teacher-controlled**: كشف تدريجي بـ Space — نفس النمط الموجود
6. **قابل للتوسع**: 11 نموذج يخدم 28 حرفاً × 16 محاضرة
7. **حجم صغير**: ~55-165KB لكل 28 حرف (مقارنة بـ 14MB+ للفيديو)

### 11.3 لماذا البدائل أقل جودة؟

| البديل | سبب الاستبعاد |
|--------|-------------|
| SVG ثابت فقط | لا يُظهر حركة اللسان — Doc 07 يطلب "تسلسل" |
| Lottie | يحتاج مكتبة خارجية — يتعارض مع Offline-first |
| Video | حجم كبير جداً، لا يتوافق مع الكشف التدريجي |
| CSS فقط | لا تستطيع رسم تشريح دقيق |
| 28 SVG منفصل | عبء صيانة، صعوبة ضمان الاتساق |
| مكونات فقط (بلا نماذج) | تعقيد تقني عالٍ بلا فائدة تربوية إضافية |

### 11.4 هل يحتاج قراراً جديداً؟

**نعم — هذه الوثيقة هي QD-17.**

### 11.5 Status

**Proposed** — ينتظر اعتماد المستخدم قبل التنفيذ.
