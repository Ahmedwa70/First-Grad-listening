## 2. Current Problem — المشكلة الحالية

### 2.1 التناقض بين الوثائق والتنفيذ

الكود الحالي يعرض `/b/` `/t/` `/θ/` `/n/` (رموز IPA لاتينية) كتمثيل **أوّلي** في **كل** المراحل.

الوثائق التأسيسية تقول شيئاً مختلفاً:

| الوثيقة | ما تقوله عن IPA | المرتبة |
|---------|-----------------|---------|
| Doc 04 (Instructional Blueprint) | يستخدم `/ب/` — حرف عربي | مرتبة 4 (أعلى مرجعية تنفيذية) |
| Doc 05 (Design System) | IPA = "سياق داعم"، حجم 60%، اختياري | مرتبة 3 |
| Doc 06 (Architecture) | "رمز IPA (اختياري)" | مرتبة 2 |
| Doc 07 (Implementation Map) | P2: "أيقونات الصوت نشطة. لا عنصر آخر مرئي" | مرتبة 1 (أعلى مرجعية) |
| Doc 01 (Framework) | لا يذكر IPA مطلقاً | مرتبة 7 |
| Doc 02 (Roadmap) | لا يذكر IPA مطلقاً | مرتبة 6 |
| Doc 03 (Pedagogical Blueprint) | يستخدم (ب) (ت) — لا IPA | مرتبة 5 |

**الخلاصة**: لا توجد وثيقة تأسيسية واحدة تطلب عرض IPA كتمثيل أوّلي. كلها إما تُصنّفه "اختياري/داعم" أو لا تذكره أصلاً.

### 2.2 تفاقم المشكلة عبر المراحل

الكود الحالي يستخدم `letter.phoneme` (أي `/b/` وغيره) في **كل** المراحل:

| المرحلة | موقع الظهور في الكود | عدد المرات | السياق |
|---------|---------------------|------------|--------|
| P2 | أزرار الأصوات، الفونيم النشط، خريطة الأصابع | 3 مواقع | **أوّلي** — هو الهوية البصرية للصوت |
| P3 | زر الفونيم، شاشة المراجعة الرباعية | 2 مواقع | مع الحرف العربي — تمثيل مكمّل |
| P4 | أزرار الصوت في المقارنة | 1 موقع | زر تشغيل صوت |
| P5 | تسمية الحرف المستهدف، لوحة المراجعة | 2 مواقع | مرجع ربط الكلمة بالحرف |
| P6 | إجابة التعرف، مقارنة نفس/مختلف، أزرار التقارب | 3 مواقع | هوية الحرف في سياق التقييم |
| P7 | ملخص المحاضرة | 1 موقع | مرجع مراجعة ختامي |

**المجموع: 12 موقعاً** في 6 مراحل يعرض IPA لاتيني كتمثيل أوّلي.

### 2.3 ملاحظة حاسمة عن P3

في P3 (ربط الصوت بالحرف) يوجد عنصر `ipa-badge` منفصل:

```javascript
<span class="ipa-badge">IPA: /${letter.ipa}/</span>
```

هذا يعني أن الكود يعرض الفونيم **مرتين** في P3:
1. `letter.phoneme` (`/b/`) — في زر الفونيم
2. `letter.ipa` (`b`) — في شارة IPA

هذا التكرار يؤكد أن `phoneme` لم يُصمَّم ليكون IPA — بل هوية الصوت. IPA له حقل منفصل (`ipa`) وعرض منفصل (`ipa-badge`).

## 3. Cross-Phase Analysis — تحليل عبر المراحل

### 3.1 خريطة الدور التعليمي لكل ظهور

| المرحلة | ما يُعرض حالياً | الهدف التعليمي الفعلي | هل يمثل صوتاً أم حرفاً أم مرجعاً؟ | ما يجب عرضه |
|---------|-----------------|----------------------|-----------------------------------|-------------|
| P1 | لا تمثيل صوتي | تهيئة وترحيب | — | — |
| P2 (أزرار) | `/b/` `/t/` `/θ/` `/n/` | **هوية الصوت** — الطالب يختار صوتاً ليسمعه | هوية صوت | **هوية الصوت** بأي تمثيل يخدم التمييز |
| P2 (نشط) | `/b/` | **تأكيد** — أي صوت يعمل الآن | مرجع حالة | **تأكيد بصري** للصوت المختار |
| P2 (أصابع) | `/b/` مع رقم | **ربط** رقم الإصبع بالصوت | مرجع ربط | **رمز ربط** بين الرقم والصوت |
| P3 (زر فونيم) | `/b/` | **ربط الصوت بالحرف** — الطالب يرى الحرف ويسمع صوته | صوت مرتبط بحرف | `/ب/` — الربط أصبح مباشراً |
| P3 (ipa-badge) | `IPA: /b/` | **مرجع أكاديمي** — للمعلم أو الطالب المتقدم | مرجع تقني | IPA يبقى كـ badge اختياري |
| P3 (رباعي) | `/b/` | زر تشغيل صوت في المراجعة | مرجع | `/ب/` |
| P4 (مقارنة) | `/b/` | زر تشغيل صوت الحرف | مرجع | `/ب/` |
| P5 (تسمية) | `باء — /b/` | تسمية الحرف المستهدف في الكلمة | مرجع هوية | `باء — /ب/` |
| P5 (مراجعة) | `/b/` | لوحة مراجعة الكلمة | مرجع | `/ب/` |
| P6 (إجابة) | `باء — /b/` | كشف الإجابة الصحيحة | مرجع تعريف | `باء — /ب/` |
| P6 (مقارنة) | `ب /b/` vs `ت /t/` | مقارنة صوتين مختلفين | مرجع تمييز | `ب /ب/` vs `ت /ت/` |
| P6 (تقارب) | `/b/` | أزرار أصوات متقاربة | مرجع | `/ب/` |
| P7 (ملخص) | `باء — /b/` | ملخص ختامي | مرجع | `باء — /ب/` |

### 3.2 الاستنتاج من التحليل العابر للمراحل

1. **`letter.phoneme` ليس IPA** — هو **هوية الصوت** المعروضة للطالب. IPA له حقل منفصل (`letter.ipa`) وعرض منفصل (`ipa-badge`).

2. **هوية الصوت تظهر في 12 موقعاً عبر 6 مراحل** — هذا يعني أن تغيير `phoneme` من `/b/` إلى `/ب/` يؤثر على النظام بالكامل، وهذا بالضبط ما يجعله قراراً تأسيسياً وليس تعديل P2.

3. **دور IPA الأكاديمي محفوظ** — حقل `letter.ipa` و `ipa-badge` في P3 يبقيان كطبقة مرجعية اختيارية. القرار لا يحذف IPA — بل يُعيد وضعه في مكانه الصحيح.

## 4. Data Architecture Analysis — تحليل بنية البيانات

### 4.1 الهيكل الحالي في `lesson-01.js`

```javascript
{
  id:            'ba',
  char:          'ب',         // الحرف العربي
  name:          'باء',       // اسم الحرف
  phoneme:       '/b/',       // ← هوية الصوت المعروضة (IPA حالياً)
  ipa:           'b',         // ← IPA الأكاديمي (يُعرض في ipa-badge)
  chinesePinyin: '吧 (bā)',   // ← التقريب الصيني
  audioFile:     'assets/audio/ba.mp3',
  // ...
}
```

### 4.2 تحليل الطبقات

الهيكل الحالي يحتوي فعلاً على **ثلاث طبقات تمثيل**:

| الطبقة | الحقل | المحتوى الحالي | الدور الفعلي |
|--------|-------|----------------|-------------|
| **هوية الصوت** (Student-facing) | `phoneme` | `/b/` | المعروض للطالب في كل المراحل |
| **المرجع الأكاديمي** (Teacher/Reference) | `ipa` | `b` | المعروض في `ipa-badge` بـ P3 فقط |
| **التقريب اللغوي** (L1 Bridge) | `chinesePinyin` | `吧 (bā)` | المعروض في `chinese-hint` بـ P3 فقط |

**المشكلة**: طبقة "هوية الصوت" (التي يراها الطالب في كل مكان) تحتوي IPA لاتيني — بينما يجب أن تحتوي التمثيل الأقرب للنظام المستهدف (العربية).

### 4.3 الهيكل المقترح — بدون تغيير بنيوي

```javascript
{
  id:            'ba',
  char:          'ب',
  name:          'باء',
  phoneme:       '/ب/',       // ← هوية الصوت = الحرف العربي بين شرطتين
  ipa:           'b',         // ← IPA الأكاديمي — يبقى كما هو
  chinesePinyin: '吧 (bā)',   // ← التقريب الصيني — يبقى كما هو
  audioFile:     'assets/audio/ba.mp3',
}
```

**لا تغيير بنيوي مطلوب** — فقط تغيير قيم حقل `phoneme`.

### 4.4 الهيكل المستقبلي المثالي (لا يُنفّذ الآن)

```javascript
{
  id:            'ba',
  char:          'ب',
  name:          'باء',
  
  // طبقة العرض — ما يراه الطالب
  display: {
    soundLabel:  '/ب/',        // هوية الصوت في كل المراحل
  },
  
  // طبقة المرجع — ما يراه المعلم/المتقدم
  reference: {
    ipa:           'b',
    chinesePinyin: '吧 (bā)',
    articulationNote: 'شفوي انفجاري مجهور',
  },
  
  // طبقة الصوت
  audio: {
    phonemeFile: 'assets/audio/ba.mp3',
    nameFile:    null,  // مؤجل — QD-06
  },
}
```

هذا الهيكل يفصل صراحة بين:
- **Student Layer**: ما يراه الطالب
- **Teacher/Reference Layer**: ما يراه المعلم أو الطالب المتقدم
- **Audio Layer**: ملفات الصوت

لكن التنفيذ الحالي لا يحتاج هذا التغيير البنيوي — تغيير قيمة `phoneme` يكفي.

## 5. SLA Analysis — تحليل اكتساب اللغة الثانية

### 5.1 مسار اكتساب الصوت الجديد

```
المرحلة 1: التعرض الصوتي النقي
    ↓ (P2: الاستماع الصامت)
المرحلة 2: التمييز السمعي
    ↓ (P2: عدّ الأصوات بالأصابع)
المرحلة 3: التقليد الجماعي
    ↓ (P2: الترديد الجماعي)
المرحلة 4: التصحيح الحركي
    ↓ (P2: تصحيح الثاء)
المرحلة 5: الربط بالشكل المكتوب
    ↓ (P3: الكشف التدريجي)
المرحلة 6: التعرف في سياق الكلمة
    ↓ (P5: الكلمات)
المرحلة 7: التقييم والتثبيت
    ↓ (P6-P7: التمييز السمعي والتقييم)
```

### 5.2 أي تمثيل بصري يخدم كل مرحلة؟

| مرحلة الاكتساب | ما يحتاجه الطالب بصرياً | IPA يخدم؟ | الحرف العربي يخدم؟ |
|----------------|------------------------|-----------|-------------------|
| 1. التعرض الصوتي | **لا شيء** — صوت فقط | ❌ يشوّش | ❌ يشوّش |
| 2. التمييز السمعي | مرجع للتمييز (رقم/لون) | ⚠️ مرجع أجنبي | ⚠️ يكشف الحرف مبكراً |
| 3. التقليد | مرجع بصري لتأكيد الصوت | ⚠️ غريب | ✅ سيراه لاحقاً |
| 4. التصحيح الحركي | مرجع حركي (صورة اللسان) | ❌ لا علاقة | ❌ لا علاقة |
| 5. ربط الصوت بالحرف | **الحرف العربي** | ❌ وسيط غير مطلوب | ✅ هو الهدف |
| 6. التعرف في كلمة | الحرف ضمن كلمة | ❌ | ✅ |
| 7. التقييم | مرجع للمقارنة | ⚠️ | ✅ |

**الاستنتاج**: IPA لا يخدم أي مرحلة بشكل أفضل من الحرف العربي. الحرف العربي يتفوق في المراحل 3 و5 و6 و7 لأنه النظام المستهدف.

### 5.3 الترتيب الأمثل: Sound → Imitation → Discrimination → Letter

الترتيب الأمثل من منظور SLA هو **Model C**:

```
الصوت (سمعي نقي)
    ↓
التقليد (إنتاج حركي)
    ↓
التمييز (مقارنة سمعية)
    ↓
الحرف (ربط بالشكل المكتوب)
```

هذا الترتيب مطابق لما تصفه وثيقة Doc 04 (Instructional Blueprint) لمراحل P2:
- 2.1 الاستماع الصامت (صوت)
- 2.2 الترديد الجماعي (تقليد)
- 2.3 عدّ الأصوات بالأصابع (تمييز)
- 2.4 التصحيح الصوتي (تصحيح حركي)

**IPA لا يظهر في أي مرحلة من هذا التسلسل.** الحرف العربي لا يظهر إلا في P3 (المرحلة التالية).

## 6. IPA Neutral Assessment — تقييم محايد لـ IPA

### 6.1 متى يكون IPA مفيداً؟

| السياق | مستوى الفائدة | التبرير |
|--------|---------------|---------|
| **طلاب لغويات** (Linguistics students) | ✅ عالٍ | يحتاجون نظام ترميز دقيق مشترك عالمياً |
| **معلمون** (Reference) | ✅ عالٍ | مرجع دقيق لمخارج الحروف |
| **متعلمون متقدمون** (B1+) | ✅ متوسط | يساعد في تصحيح النطق الدقيق |
| **متعلمون متوسطون** (A2-B1) | ⚠️ منخفض | قد يساعد لكنه ليس ضرورياً |
| **مبتدئون A0** | ❌ ضار | نظام رمزي إضافي يُزاحم الحمل المعرفي |
| **أطفال** | ❌ غير مناسب | تجريد فوق قدرتهم |

### 6.2 متى يصبح IPA عبئاً؟

1. **عندما يكون Student-facing في A0**: الطالب يتعلم نظاماً كتابياً جديداً (العربية). إضافة IPA = نظام ثالث يتنافس على الموارد المعرفية.

2. **عندما يُنشّط تداخلاً لغوياً**: للطلاب الصينيين، `/b/` يُنشّط بينيين `b` (غير مجهور). للطلاب الإسبان، `/b/` يُنشّط `/β/` (احتكاكي). كل مجموعة لغوية تُنشّط ربطاً مختلفاً — وكلها خاطئة للعربية.

3. **عندما يفشل مع الأصوات الفريدة**: (انظر القسم 8)

### 6.3 الحكم: IPA = Teacher/Reference Layer

IPA يجب أن يكون:
- **موجوداً في البيانات** (`letter.ipa`) — ✅ موجود حالياً
- **متاحاً في واجهة المراجعة** (`ipa-badge` في P3) — ✅ موجود حالياً
- **غير معروض كتمثيل أوّلي** للطالب — ❌ هذا ما يجب تغييره

## 7. Global Learner Analysis — تحليل عالمي للمتعلمين

### 7.1 تأثير IPA حسب اللغة الأم

| اللغة الأم | نظام الكتابة | علاقة بالحروف اللاتينية | تأثير IPA اللاتيني |
|------------|-------------|------------------------|-------------------|
| **الصينية** | لوغوغرافي | بينيين (تحويل صوتي لاتيني) | ❌ تداخل مزدوج: بينيين + إنجليزية |
| **اليابانية** | مقطعي + كانجي | رومانجي (تحويل لاتيني) | ❌ تداخل مشابه للصينية |
| **الكورية** | هانغول (أبجدي مستقل) | رومانية (تحويل لاتيني) | ⚠️ تداخل متوسط |
| **الإنجليزية** | لاتيني | مباشر | ⚠️ وهم الإتقان الكاذب (b = /b/ "أعرف هذا") |
| **الفرنسية** | لاتيني | مباشر | ⚠️ نفس المشكلة + تداخل نطقي فرنسي |
| **الإسبانية** | لاتيني | مباشر | ⚠️ `/b/` = `/β/` احتكاكي إسباني |
| **التركية** | لاتيني | مباشر | ⚠️ بعض الحروف مختلفة (c = /dʒ/) |
| **الأوردو/الفارسية** | عربي مُعدّل | لا | ✅ الحرف العربي مألوف — لا حاجة لـ IPA |
| **الماليزية/الإندونيسية** | لاتيني | مباشر | ⚠️ تداخل متوسط |
| **الهندية** | ديفاناغري | رومانية (تحويل) | ⚠️ تداخل خفيف |

### 7.2 الاستنتاج العالمي

**لا توجد مجموعة لغوية واحدة يُفيدها IPA كتمثيل أوّلي في مستوى A0.**

- المتعلمون من خلفيات لاتينية: يقعون في "وهم الإتقان الكاذب"
- المتعلمون من خلفيات غير لاتينية: يتعاملون مع نظام ثالث غريب
- المتعلمون من خلفيات عربية/فارسية: لا يحتاجون IPA أصلاً

**الحرف العربي هو النظام المستهدف لكل المتعلمين** — بغض النظر عن خلفيتهم اللغوية.

### 7.3 الطالب الصيني — الحالة المركزية

بالإضافة للتحليل العالمي أعلاه، الطالب الصيني يواجه تداخلاً فريداً:

1. **تداخل البينيين**: `b` في بينيين = صوت غير مجهور (unaspirated voiceless). العربي `ب` = مجهور (voiced). رؤية `/b/` تُنشّط النطق الخاطئ.

2. **ميزة الانقطاع الكتابي**: العربية مختلفة كلياً عن الصينية — المخ يتعامل معها كنظام مستقل. إدخال حروف لاتينية يُدمّر هذه الميزة.

3. **صوت θ**: لا وجود له في الصينية أو البينيين أو الإنجليزية الصينية. رمز `/θ/` غريب تماماً بينما `/ث/` يبني جسراً نحو P3.

## 8. Difficult Arabic Sounds Analysis — اختبار على الأصوات الصعبة

### 8.1 اختبار الاستراتيجية على جميع الأصوات العربية

| ب | /b/ | تداخل بينيين/إنجليزي | /ب/ | لا مشكلة |

| ء | /ʔ/ | رمز غريب | /ء/ | لا مشكلة |

### 8.2 النتيجة

**IPA يفشل مع 14 صوتاً من 28** (الأصوات المظللة بالخط العريض) — إما رمز غريب، أو تركيب مزدوج، أو تداخل نشط.

**الحرف العربي يعمل مع 28/28** — لأن كل صوت عربي له حرف عربي بتعريفه.

**بحلول المحاضرة 4** (حيث تُقدَّم ع غ ح خ): نصف الرموز المعروضة ستكون رموز IPA لا يعرفها الطالب — فيتحول "النظام المساعد" إلى عبء.

### 8.3 قابلية التوسع

| المعيار | IPA اللاتيني | الحرف العربي |
|---------|-------------|-------------|
| عدد الأصوات المدعومة بلا مشاكل | 14/28 (50%) | 28/28 (100%) |
| هل يحتاج تعليمه قبل استخدامه؟ | نعم — من المحاضرة 3+ | لا — هو النظام المستهدف |
| هل يعمل مع التفخيم؟ | لا — يحتاج diacritics مركّبة | نعم — حرف مستقل |
| هل يعمل مع الحروف الحلقية؟ | لا — رموز غريبة | نعم — حروف مألوفة |
| اتّساق النظام | يتدهور مع كل مجموعة جديدة | ثابت — كل حرف له شكل |

## 10. Final Decision — القرار النهائي

### القرار الأول: وفقاً لفلسفة المشروع الحالية

**الخيار: Model B المعدّل — الحرف العربي بين الشرطتين كهوية صوت**

#### التغيير

```
phoneme: '/b/'  →  phoneme: '/ب/'
phoneme: '/t/'  →  phoneme: '/ت/'
phoneme: '/θ/'  →  phoneme: '/ث/'
phoneme: '/n/'  →  phoneme: '/ن/'
```

#### المبررات

1. **مطابقة الوثيقة التأسيسية**: Doc 04 يستخدم `/ب/` صراحة — لا يوجد مبرر موثّق للتمثيل اللاتيني.

2. **IPA يبقى في مكانه الصحيح**: حقل `letter.ipa` و `ipa-badge` في P3 لا يتأثران — IPA يبقى كطبقة مرجعية اختيارية، وهذا بالضبط ما تصفه Doc 05 ("سياق داعم") و Doc 06 ("اختياري").

3. **تصفير التداخل اللاتيني**: لكل المتعلمين — ليس فقط الصينيين.

4. **قابلية التوسع الكاملة**: يعمل مع 28/28 صوتاً عربياً بلا استثناء.

5. **التنفيذ البسيط**: تغيير 4 قيم نصية في ملف بيانات واحد. لا تغيير HTML/CSS/JS.

6. **الاتّساق عبر المراحل**: `/ب/` في P2 = `ب` في P3 = `ب` في كل المراحل — لا تبديل أنظمة.

#### ما لا يتغير

- حقل `ipa` — يبقى كما هو
- حقل `chinesePinyin` — يبقى كما هو
- عنصر `ipa-badge` في P3 — يبقى كما هو
- عنصر `chinese-hint` في P3 — يبقى كما هو
- بنية HTML — لا تغيير
- ملفات CSS — لا تغيير (يجب إعادة قياس `min-width` في `.active-phoneme`)
- منطق JS — لا تغيير

### القرار الثاني: التوصية المستقلة للخبير

**الخيار: Model E (Multi-Layer) + Model D (Phase-Based) = نظام طبقي تكيّفي**

لو كنت أبني هذا النظام من الصفر بدون أي قيود:

#### المعمارية المثالية

**طبقة البيانات الداخلية** (لا تتغير أبداً):
```
sound_id: 'ba'
arabic_char: 'ب'
arabic_name: 'باء'
ipa: 'b'
articulation: { place: 'bilabial', manner: 'plosive', voicing: 'voiced' }
pinyin_approx: '吧 (bā)'
audio_files: { phoneme: 'ba.mp3', name: null }
```

**طبقة العرض** (تتغير حسب المرحلة):

| المرحلة | النشاط | ما يُعرض | المبرر |
|---------|--------|---------|--------|
| P2 - 2.1 | استماع صامت | **لا شيء** — شاشة صوت فقط | ترميز صوتي معزول |
| P2 - 2.2 | ترديد جماعي | **لون + رقم** (① ② ③ ④ بلون الحرف) | مرجع محايد — لا يُنشّط أي نظام كتابي |
| P2 - 2.3 | عدّ بالأصابع | **أصابع + رقم** | يعكس الفعل الجسدي |
| P2 - 2.4 | تصحيح الثاء | **رسم حركي** (لسان بين أسنان) | تصحيح حركي — ليس رمزياً |
| P3 | ربط بالحرف | **الحرف العربي** (كشف تدريجي) + IPA badge اختياري | هذا هو لحظة الربط |
| P4 | الكتابة/النقاط | **الحرف العربي** | ممارسة حركية |
| P5 | الكلمة | **الحرف في سياق الكلمة** | بناء المعنى |
| P6 | التمييز السمعي | **الحرف + اللون** | تقييم |
| P7 | ملخص | **الحرف + الاسم** | مراجعة |

#### لماذا يختلف عن Model B؟

Model B (الحرف العربي بين شرطتين) **أفضل بكثير** من الوضع الحالي — لكن:

1. يكشف شكل الحرف في P2 — قبل P3 ("الكشف التدريجي")
2. يستخدم نفس التمثيل في كل المراحل — بينما كل مرحلة لها هدف تعليمي مختلف

Model E+D يحترم حرفياً مبدأ "الصوت أولاً" ومبدأ "الكشف التدريجي":
- في P2: الطالب لا يرى أي حرف — يسمع فقط
- في P3: لحظة الكشف تكون حقيقية — أول مرة يرى الحرف

#### لماذا لا يُنفَّذ الآن؟

يتطلب:
- إضافة `sub-activity display mode` في بنية البيانات
- تعديل ENGINE ليُبدّل العرض حسب النشاط
- تصميم أصول بصرية جديدة (موجات، أصابع، رسم حركي)
- اختبار مكثف عبر كل المراحل

**Model B هو الخطوة الأولى الصحيحة في الاتجاه الصحيح.**

يمكن الترقية من B إلى E+D لاحقاً — البنية الحالية لا تمنع ذلك.

## 11. Global Rule vs Phase-Specific Rule

### السؤال: هل التمثيل يجب أن يكون قاعدة عامة أم خاصة بكل مرحلة؟

### الجواب: **Phase-Specific Controlled Representation** هو الأمثل نظرياً — لكن **Global Rule** هو الممكن عملياً الآن.

| النهج | الوصف | الجدوى الحالية | الجدوى المستقبلية |
|-------|-------|----------------|-------------------|
| **Global Rule** | `/ب/` في كل المراحل | ✅ فورية | يبقى صحيحاً |
| **Phase-Specific** | تمثيل مختلف حسب المرحلة والنشاط | ❌ يحتاج تغييرات معمارية | ✅ عندما يُطوّر ENGINE |

**القرار**: اعتماد **Global Rule** الآن (Model B) مع توثيق أن **Phase-Specific** هو الهدف المستقبلي.

## 16. الإجابة الصريحة على السؤال المركزي

> هل يجب:
> A) الإبقاء على IPA في كل المراحل؟
> B) حذف IPA من واجهة الطالب؟
> C) جعل IPA طبقة للمعلم فقط؟
> D) استخدام نظام مرحلي؟
> E) بناء Adaptive Representation حسب النشاط؟

### الجواب:

**C + E** — على مرحلتين:

**المرحلة الأولى (الآن)**: **C** — IPA يصبح طبقة مرجعية فقط (`ipa-badge` في P3). هوية الصوت المعروضة للطالب تصبح الحرف العربي بين شرطتين (`/ب/`). هذا يحقق C بأبسط تنفيذ.

**المرحلة الثانية (مستقبل)**: **E** — بناء Adaptive Representation حسب النشاط والمرحلة. كل نشاط يُقرر ما يعرضه بناءً على هدفه التعليمي.
