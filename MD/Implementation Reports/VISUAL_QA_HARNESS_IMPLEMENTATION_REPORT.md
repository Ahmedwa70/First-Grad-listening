# Visual QA Harness — Implementation Report

## الهدف

بناء قدرة تحقق بصري **متكررة وقابلة للقياس** لتعديلات الواجهات الرسومية، بعد أن
اعتمد المشروع حتى الآن على لقطات يدوية تُرسل للفحص بالعين. اليدوي يكشف العطل بعد
وقوعه، ولا يكشفه في المقاسات التي لم يُلتَقط فيها، ولا يمنع عودته لاحقاً.

الناتج: `tools/visual/` — أداة بلا اعتماديات خارجية تقود Brave بلا واجهة عبر
CDP، وتلتقط لقطات **متعددة المقاسات** لكل سيناريو، مع **فحوص عددية** تُنفَّذ على
المتصفح نفسه بعد استقرار الرسم.

## لماذا قياسات لا لقطات فقط

اللقطة وحدها تنتج «نجاحاً كاذباً»: بعض الأعطال لا تُقرأ إلا بقياس النص داخل
صندوقه. المثال الحاضر أثبته —

الفحص الأولي قارن **صندوق** الكبسولة بحدود البطاقة، فمرّ ناجحاً، لأن الكبسولة
كانت **منضغطة** (`flex-shrink: 1`) داخل طبقة `position: absolute` في بطاقة
`overflow: hidden`: صندوقها داخل البطاقة، أما نصّها فمقطوع من الداخل.
الفحص الصحيح يقيس `scrollHeight` مقابل `clientHeight`، وهو ما كشف العطل:
**22px ظاهر من 45px**.

قرارات التنفيذ:

1. **مسار المعلم الحقيقي**: الخطوات نقرات فعلية على أزرار الواجهة
   (`.p6-reveal-btn`، `.p6-next-btn`، أزرار الجولات) أو مفاتيح حقيقية عبر
   `Input.dispatchKeyEvent` — لا استدعاء داخلي متجاوز للواجهة، فيبقى السيناريو
   صالحاً حتى لو تغيّر المنطق الداخلي.
2. **حالة نظيفة لكل قياس**: تقدّم الدرس يُحفظ في `localStorage`، فبقاؤه بين
   المقاسات يفتح نافذة «هل تستكمل الحصة؟». الأداة تُفرّغ التخزين وتُعيد التحميل،
   ثم تتحقق من غياب أي طبقة حاجبة قبل القياس.
3. **لا كتابة خارج المشروع**: بروفايل المتصفح في `.tools/brave-profile-<pid>`
   ويُحذف بعد التشغيل؛ لا تثبيت ولا تعديل على إعدادات المتصفح الشخصي.
4. **الفشل مرئي**: رمز خروج ≠ 0 عند أي فحص فاشل، والتنبيهات الشعرية (<2px)
   مفصولة عن الفشل حتى لا يغرق العطل الحقيقي في ضجيج.

## السبب الجذري للعطل

> **حُدِّث:** نُفِّذ الإصلاح والتحقق بعد هذا التشخيص — التفاصيل في
> `MD/Implementation Reports/P6_D3_LABEL_CLIPPING_FIX_REPORT.md`.

القالب المضغوط للشاشات القصيرة في `css/style.css`:

```css
@media (max-height: 720px) {            /* السطر 6268 */
  .p6-d3-reveal-card,
  .p6-d3-letter-card { min-height: clamp(90px, 14vh, 140px); }   /* 6283 */
  .p6-d3-lc-char    { font-size: clamp(2.5rem, 4.5vw, 3.5rem); } /* 6284 */
}
```

عند ارتفاع 672px: `14vh = 94.08px` ⇒ البطاقة 94.08px، وصندوق الحشو الصافي ≈
**89px**، بينما المحتوى المطلوب = الحرف (56px) + الفراغ (8.8px) + الكبسولة
بطبيعتها (**45px** بسبب `line-height: normal` في Noto Naskh) ≈ **110px**.
فينضغط العنصر المرن (الكبسولة) إلى 22px، ويقصّ `overflow: hidden` نصَّها.

ويبقى النطاق **641–900px بلا حماية**: الحارس القائم في
`css/style.css:7842-7863` محصور في `@media (max-height: 640px)`، أي تحت هذا
النطاق فلا يعالجه.
